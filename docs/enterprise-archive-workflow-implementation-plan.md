# خطة تنفيذ نظام إدارة الأرشيف وتداول الملفات
## Enterprise Archive Workflow Implementation Plan

## 1) الهدف
تنفيذ نظام متكامل لإدارة الأرشيف وتداول الملفات يحقق:
- أمان عالي
- تتبع كامل لحركة الملف
- دعم طلبات النسخ الرقمية والأصل الورقي
- بوابة خارجية آمنة للبنوك
- قابلية التوسع والتدقيق

## 2) النطاق
يشمل:
- إدارة المستخدمين والصلاحيات
- إدارة العملاء وملفاتهم ومستنداتهم
- دورة حياة الملف
- طلبات التحويل والتسليم والاستلام والإرجاع
- التتبع والسجلات
- البحث والباركود
- مشاركة رقمية آمنة للبنوك

لا يشمل حاليا:
- OCR متقدم
- منع لقطات الشاشة (غير ممكن تقنيا بنسبة 100%)

## 3) نموذج التشغيل المستهدف
الإدارات:
- archive
- collection
- legal
- bank
- super_admin

أنواع الطلب:
- physical
- digital

حالات دورة الحياة:
- archived
- requested
- transferred
- in_legal
- in_collection
- digital_shared
- returned
- locked

## 4) نموذج البيانات المستهدف
المجموعات الأساسية:
- users
- departments
- clients
- client_files
- documents
- transfer_requests
- transfers
- activity_logs
- notifications
- shared_links

حقول حاسمة:
- currentHolder في client_files
- locked في client_files
- status في client_files
- requestType في transfer_requests
- fromDepartment و toDepartment في transfers
- actor و action و timestamp في activity_logs

## 5) مراحل التنفيذ

## المرحلة 0: التحضير والتحليل
الهدف:
تثبيت خط الأساس قبل أي تغيير.

المهام:
- حصر الوضع الحالي للأدوار والإدارات والحماية
- تحديد الفجوات بين النظام الحالي والوركفلو المستهدف
- اعتماد مصفوفة صلاحيات نهائية لكل إدارة

المخرجات:
- تقرير فجوات
- مصفوفة صلاحيات معتمدة

معيار القبول:
- موافقة أصحاب المصلحة على الفجوات والأولويات

---

## المرحلة 1: توحيد الهوية والصلاحيات
الهدف:
توحيد الأدوار والصلاحيات بين الواجهة وقواعد Firestore وFunctions.

المهام:
- تعريف أدوار موحدة نهائيا
- توحيد department scope
- ربط الصلاحيات على مستوى الصفحة والعملية
- إغلاق أي مسار وصول غير مصرح

المخرجات:
- Role and Permission Contract
- مصفوفة Page Access محدثة

معيار القبول:
- كل دور يرى فقط الصفحات والعمليات المصرح بها

---

## المرحلة 2: بناء نواة البيانات
الهدف:
إطلاق بنية العملاء والملفات والمستندات.

المهام:
- إنشاء clients
- إنشاء client_files
- ربط documents بملف العميل
- إضافة barcode في مستوى الملف
- دعم البيانات الأساسية:
  - Client Name
  - Client ID
  - Barcode
  - National ID
  - Contract Number
  - Case Number

المخرجات:
- CRUD كامل للعميل وملفه
- ربط مستندات صحيح

معيار القبول:
- يمكن إنشاء عميل وملفه وإرفاق مستندات ثم أرشفته

---

## المرحلة 3: دورة حياة الملف وقفل الأصل
الهدف:
تطبيق حالات الملف وقواعد القفل.

المهام:
- تطبيق status state machine
- تفعيل locked عند خروج الأصل الورقي
- منع طلب أصل جديد إذا الملف خارج الأرشيف
- السماح بطلب نسخة رقمية دون قفل

المخرجات:
- محرك انتقال حالات واضح
- تحقق قواعد Lock على مستوى backend

معيار القبول:
- لا يمكن كسر قواعد القفل عبر الواجهة أو API

---

## المرحلة 4: Workflow الطلبات والتحويل
الهدف:
تطبيق دورة طلب الملف من النهاية للنهاية.

المهام:
- transfer_requests:
  - create
  - review
  - approve or reject
- transfers:
  - dispatch
  - receive
  - return
- تحديث currentHolder تلقائيا مع كل حركة

المخرجات:
- workflow فعلي للطلبين physical و digital
- سجل chain of custody كامل

معيار القبول:
- كل انتقال له سجل زمني ومستخدم مسؤول وحالة دقيقة

---

## المرحلة 5: النسخ الرقمية والمشاركة الآمنة
الهدف:
تنفيذ مشاركة رقمية آمنة للإدارات والبنوك.

المهام:
- تطبيق View Only للبنك و التوريق
- منع download و print و edit للبنك و التوريق
- إضافة watermark ديناميكي:
  - Username
  - IP Address
  - Date and Time

المخرجات:
- Secure Viewer متكامل
- سياسات وصول منفصلة للبنك و التوريق

معيار القبول:
- البنك و التوريق يرى فقط الملفات المصرح بها وبوضع قراءة آمن

---

## المرحلة 6: Activity Logs والتدقيق
الهدف:
تتبع كامل لكل العمليات الحساسة.

المهام:
- تسجيل:
  - فتح ملف
  - تعديل
  - تحميل
  - طباعة
  - بحث
  - تحويل
  - إرجاع
- تسجيل before and after للتعديلات الحساسة
- تصنيف السجلات حسب نوع الحدث وخطورته

المخرجات:
- Activity Logging موحد
- تقارير تدقيق قابلة للبحث

معيار القبول:
- كل عملية حساسة لها أثر تدقيقي كامل

---

## المرحلة 7: البحث والباركود
الهدف:
تسريع الوصول للملف وتقليل زمن الاسترجاع.

المهام:
- بحث حسب:
  - Barcode
  - Client Name
  - Client ID
  - Contract Number
  - Case Number
- Workflow:
  - Scan Barcode
  - Open Client File
- تحسين الفهارس المطلوبة في Firestore

المخرجات:
- بحث سريع ودقيق
- فتح مباشر للملف عبر الباركود

معيار القبول:
- زمن استرجاع ضمن الهدف التشغيلي المتفق عليه

---

## المرحلة 8: التقارير والاستقرار والإطلاق
الهدف:
إطلاق تدريجي آمن مع مراقبة ورجوع سريع.

المهام:
- تقارير تشغيلية:
  - الملفات داخل كل إدارة
  - الطلبات المفتوحة
  - زمن التسليم والإرجاع
  - الملفات المقفلة
- اختبارات قبول شاملة
- خطة نشر تدريجية
- خطة rollback واضحة

المخرجات:
- Production rollout checklist
- Runbook تشغيلي

معيار القبول:
- نجاح الإطلاق دون خروقات صلاحيات أو فقد تتبع

## 6) معايير القبول العامة
- لا يوجد وصول غير مصرح
- كل حركة ملف مسجلة
- قواعد locked لا يمكن تجاوزها
- البنك يعمل في وضع قراءة فقط
- كل حالة ملف لها انتقالات صحيحة ومضبوطة
- جميع السجلات التدقيقية متاحة للتتبع

## 7) المخاطر وخطة التخفيف
المخاطر:
- تضارب الصلاحيات بين الواجهة والقواعد
- انتقالات حالة غير منضبطة
- فجوات في تتبع الحيازة
- مشاركة غير آمنة للنسخ الرقمية

التخفيف:
- فرض القرار النهائي في Firestore Rules وFunctions
- اختبارات حالة لكل انتقال
- منع أي تحديث مباشر للحالات خارج workflow
- استخدام روابط مؤقتة وتوقيع صلاحية للمشاركة

## 8) مؤشرات النجاح
- زمن إيجاد ملف عبر البحث والباركود
- نسبة الطلبات المكتملة ضمن SLA
- نسبة أخطاء الصلاحيات
- نسبة الملفات بلا سجل تسليم أو إرجاع
- عدد محاولات وصول مرفوضة للبنك
